## 版本说明

本次版本重点补齐了企业微信日程 skill 在真实业务编排中的关键能力，并完成了发布前的示例清理与文档泛化，便于直接接入对话式助理或自动化流程。

## 新增能力

- 支持按部门名称、部门路径和自然语言组织短语批量解析参会人
- 新增 `preview-department-attendees`，可先预览组织样本成员再决定是否创建日程
- 新增 `prepare-schedule-create`，支持先做组织识别、人员确认和日历解析，再一次性创建完整日程
- 支持 `create-meeting`，用于在日程创建后按用户确认追加创建会议
- 新增用户级 `cal_id` 本地绑定机制，支持首次自动创建并持久化用户日历
- 新增 `schedule_id -> meeting_id` 本地关联存储，支持基于刚创建的日程继续创建会议并保持可追踪关系

## 对话编排优化

- 推荐默认先解析组织和参会人，再一次性创建完整日程，不再默认先建日程再补加参会人
- 用户未明确提供主题或内容时，skill 层可先生成可用草案，再视情况追问是否需要进一步拟定
- 默认先创建日程，不自动创建会议；仅在用户明确确认后才追加创建会议
- 用户确认创建会议时，优先复用刚创建日程返回的 `schedule_id`
- 若同一条日程已经关联过会议，优先返回已有会议关联，避免重复创建

## 文档与模板更新

- 更新 `README.md`、`SKILL.md`、`references/configuration.md`、`references/getting-started.md`
- 新增通用请求模板：
  - `create-schedule-request-path.json`

  - `create-meeting-request.json`

- 清理发布前的敏感与测试示例内容，统一替换为通用占位示例
- 补充会议关联配置项：`WECOM_SCHEDULE_MEETING_LINKS_PATH`

## 使用前请注意

- 发布后仍建议通过环境变量或安全配置注入 `WECOM_CORP_SECRET`、`GITHUB_TOKEN` 等敏感值
- 如果企业微信应用启用了可信 IP，请先确认运行环境出口 IP 已加白
- 若要使用用户级日历绑定，请妥善保存本地绑定文件和审计日志
